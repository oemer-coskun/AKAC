# Threat model and deployment boundary

## Assets

Source content, existence metadata, embeddings and index metadata, generated text, persistent memories, grants, service and administrator credentials, lineage, policy bundles and audit records.

## Untrusted

User and model text; document instructions; model citations; request fields; agent proposals; unverified provenance claims; identity-provider attributes beyond the mapped subject. A document saying "administrator approved" is not an approval.

## Trusted computing base

Identity provisioning, authoritative labels, credential bindings, the core engine and its dependencies, database transactions and roles, OS isolation and the trusted runtime that mediates model and tool access. Administrators can change policies and data; this reference does not defend against compromised administrators or database owners.

## Covered attack paths

Cross-tenant and cross-role requests, scope escalation, stale and expired grants, delegation cycles, unauthorized source retrieval, laundering through summaries and memory, omitted context sources, stale derivation handles, unauthorized recipients, OPA outages, role-hierarchy and container-chain cycles or budget exhaustion, separation-of-duty bypass, and the 0.3 threats below.

## Threats added in 0.3

| Threat | Mitigation in the reference | Residual risk |
|---|---|---|
| **Embedding inversion or membership inference.** Vectors can leak information about the text they encode, and similarity scores can reveal what exists. | Embeddings and index metadata are protected derivatives carrying the document's effective label (R26). Chunk text is not stored in the index. Vectors are never returned by the agent API. One partition per classification compartment, forced RLS, optional dedicated database for `restricted`. Scores are computed only over authorized candidates, and empty results do not distinguish "no match" from "no authority". | Anyone who can read the vector database, its backups or the embedding provider's traffic may attempt inversion. Encryption at rest, key custody, network isolation and a local embedding model for `restricted` content are deployment responsibility. Timing differences are not eliminated. |
| **Filter mismatch.** A pre-filter defect, stale chunk metadata or an agent that is narrower than its user makes the index admit a chunk the caller may not read. | Compartments bound what is queried (`min(user, agent clearance)`); `decide()` re-authorizes every candidate before content, rank, score or count is observable; failures are dropped, audited and counted (`akac_filter_mismatch_total`) without content. The record stays authoritative when index and record disagree; `reconcile` repairs the index. | A sustained mismatch rate means metadata drift or a bug and needs alerting and investigation. Mismatches can reduce results for narrowly scoped agents. Recall under selective filters was measured on synthetic data only. |
| **Cross-tenant id probing.** A caller or administrator names another tenant's identifier to learn whether it exists or to overwrite it. | Tenant comes from the credential, never the body; a body naming another tenant is rejected. Record keys are `(tenant, id)`; writes cannot change a record's tenant; loads filter by tenant and row-level security applies; another tenant's id is indistinguishable from an unused one. Public responses do not reveal codes or categories. | Response-time and rate differences are not eliminated. Tenants that share a database share its availability and capacity. |
| **SCIM deprovisioning.** An identity provider removes a user but a role, SoD or provisioning error leaves access, or separation of duty blocks removal. | `active=false`, `DELETE /Users/{id}` and other pure reductions always succeed, including for a principal already in violation, and advance the tenant epoch so earlier contexts go stale. IdPs cannot smuggle roles, clearance or grants outside the mapped extension; only `security-admin` may provision; every call is audited. | Correctness depends on the identity provider actually sending the change. Bytes already delivered cannot be recalled, and model sessions must be discarded by the runtime. Reactivation needs a fresh grant. |
| **`BYPASSRLS` or superuser runtime role.** A database role that bypasses row-level security silently disables tenant isolation. | Start-up and readiness refuse such a role, transactions fail closed, loads filter by tenant independently of RLS, and tables force RLS for the owner. `AKAC_PG_ALLOW_BYPASS_RLS` exists for local development only and production refuses it. | The role model (separate owner and runtime roles, no DDL rights at runtime) must be configured by the operator; a compromised owner role defeats the design. Managed-database privilege models differ and were not tested. |
| **Admin/agent listener confusion.** An agent credential is used on the admin API, an admin credential on the agent API, or both listeners are published on one ingress. | Separate listeners, ports and credential populations; neither accepts the other's credentials; JWT audiences must differ; administrators are active users with standing roles checked and audited on every call; model output cannot reach administrative interfaces (R31). Compose places the listeners on distinct networks. | The process cannot enforce network separation. An operator who exposes the admin port to agents, or reuses a token, removes a layer of defence. The metrics listener is unauthenticated. Idempotency keys and rate limits are shared across instances only with `AKAC_SHARED_STATE=postgres` (0.6); concurrency caps stay per instance. |

## Threats addressed in 0.4

| Threat | Mitigation in the reference | Residual risk |
|---|---|---|
| **Audit rollback or truncation.** Someone with database write access deletes or rewrites the tail of a tenant audit stream. | Each stream is an RFC 9162 Merkle tree (format 2 entries, JCS leaves); signed checkpoints commit to a root; inclusion and consistency proofs let an auditor holding an earlier checkpoint detect removal or rewriting of committed history. | Only history covered by a checkpoint the verifier already holds is protected; entries after the last external checkpoint can be dropped undetected. Checkpoint signing-key custody and off-host storage of checkpoints are operator responsibility. A verifier that never compares against an older checkpoint learns nothing. |
| **Token theft and replay.** A stolen bearer token is replayed from another host. | Optional DPoP (RFC 9449) binding on the agent, admin and PDP listeners: proofs are checked for method, URL, time window and single-use `jti`, and the token's `cnf.jkt` must match the proof key. The replay cache is in-memory or PostgreSQL. | A stolen token together with its key still works until expiry or revocation. Server nonces are not implemented. An unavailable cache fails requests closed (503) rather than open. Correctness depends on the proxy forwarding method and path unchanged. |
| **Poisoned memory or knowledge.** Injected or model-written content is later retrieved as trusted. | Records carry origin and lineage; quarantine excludes a record and, optionally, its descendants from every read path; lineage queries give the blast radius; release requires an authorized administrator. Model-origin content never gains a higher trust than its sources. | Detection of poisoning is not provided; quarantine depends on someone noticing. Bytes already delivered before quarantine cannot be recalled. |
| **Erasure and retention obligations.** Data must be removed on request or on expiry, and must not be removed while under legal hold. | Erasure with optional cascade over lineage, retention policy application, legal holds that block erasure, the index reconciled afterwards, and every step audited without content. | Backups, database logs, downstream copies and provider-side data are outside AKAC. Erasure removes content but audit metadata remains by design. Index removal that fails is reported as pending, not silently ignored. |
| **Egress to unapproved destinations.** Authorized content is sent to a model provider, tool or export target that was never approved. | Destination profiles (class, maximum classification, purposes) pinned to recipients; share and export are checked against them; runs may be restricted to named destinations; the `destination_restricted` obligation lists where content may go. | The enforcement point must honour the obligation; AKAC cannot observe the actual network egress. A wrongly configured profile widens exposure. |
| **PEP confusion.** An enforcement point evaluates decisions for a tenant or subject it should not reach. | The PDP facade is a separate listener with its own credentials; the tenant is taken only from the PEP identity, never from the request; unsupported input is indistinguishable from a denial; reasons are hidden by default; every evaluation is audited. | An allow is advisory; a compromised or non-conforming PEP that ignores obligations over-discloses. Third-party PEP interoperability is untested. |

## Threats addressed by the AKAC 0.5

Contract: [RUNTIME-CONTAINMENT.md](RUNTIME-CONTAINMENT.md), [ADR-012](../governance/ADR-012-runtime-containment-contract.md). The mitigations below exist only where an operator configures runtime profile policies and runs a runtime enforcer; AKAC cannot observe the sandbox.

| Threat | Mitigation in the reference | Residual risk |
|---|---|---|
| **Policy escalation by the agent.** The agent, or content it read, loosens its own sandbox: requests another profile, edits runtime policy, or proposes policy text. | Runtime profile policies change only through the control plane (security-admin, human user, audited, epoch advance); agent credentials never reach it (R31). Obligations carry profile ids, never policy text; ids come only from stored policies, never from requests or model output; a malformed stored record defers. `ProtectedRuntime` applies exactly the decided profiles and denies on anything unsupported. | The runtime must enforce out of band and refuse policy changes from inside the sandbox; a template that is itself too permissive is applied faithfully. A compromised administrator can widen policy (audited, not prevented). |
| **Stale authorization.** Content keeps being used under an old profile after a policy change, a revocation or context expiry. | Every runtime policy change advances the tenant epoch, so open contexts deny (STALE_CONTEXT) and a fresh decision with the new profiles is needed; `max_context_ttl_ms` bounds use; the answer is re-authorized after inference. | Bytes already inside a sandbox stay there until the runtime discards them; a runtime that keeps a sandbox alive across an epoch advance with the old profile is outside AKAC's view. |
| **Agent-to-agent laundering.** An agent hands released content to another agent or sandbox with weaker containment or lower clearance. | Content moves between principals only through release, which checks the recipient, its destination profile and the run, and derives runtime profiles for the receiving decision; derived records keep the transitive classification, so `max_output_classification` cannot drop. | A direct channel between sandboxes (shared volume, network) bypasses release; the filesystem and network profiles must close it. Colluding authorized recipients remain out of scope. |
| **Audit evasion.** Protected actions happen without a matching decision, or the runtime side cannot be tied to it. | Every decision is audited in the hash-chained, provable stream with decision id, trace id and, when supplied, `executionId`; the answer's entry records the `runtimeRevision` the enforcer applied, taken only from the trusted runtime path (never from agent HTTP requests). Enforcement-point denials happen before content reaches the provider. | AKAC cannot prove that the runtime applied what it reported, nor see actions that never asked AKAC. Denials inside `ProtectedRuntime` after an allow are not separate audit entries. Runtime logs must be retained and correlated by the operator. |
| **Retrieval bypass via direct store.** The agent queries the vector index, object store or database directly and skips authorization. | Only mediated reads are authorized; indexes hold no chunk text; forced RLS and a non-bypass runtime role protect the database; network and credential profiles are the runtime-side control. | Reachability from the sandbox is an operator obligation (R118); AKAC cannot detect a direct read. Run checklist items 1, 2 and 6. |

## Structured threat models (0.6)

The tables above document the public gateway assumptions, mitigations and residual risks. A production deployment needs its own integration-specific threat assessment; this repository makes no assurance claim about separately maintained review material.

## Required integration controls

1. No agent/model access to database credentials, policy administration or authority files.
2. Per-run isolated context, including provider threads, KV caches and persistent tool state.
3. Every knowledge read recorded by the gateway; every generated disclosure passes the release gate.
4. Model provider and embedding provider/destination approved for the context's classification before any text is sent.
5. TLS, service authentication and restricted networks outside a loopback demo; agent, admin and metrics listeners on separate networks.
6. Fresh actor/group data and policy revisions from trusted provisioning; never model-derived labels.
7. Control-plane access separated from agent API access.
8. Database runtime role that is neither superuser nor `BYPASSRLS`; separate schema owner; encryption and access control for the database, vector data and backups.
9. With runtime profile policies (0.5): a runtime enforcer outside the agent's control, operator-reviewed templates for every profile id, no direct path from the sandbox to stores, providers or credentials, and the bypass checklist of [RUNTIME-CONTAINMENT.md](RUNTIME-CONTAINMENT.md).

## Residual risks and out-of-scope items

- **Timing side channels**: latency differences revealing cache hits or authorization structure are acknowledged residual risks in shared hardware (R-CACHE-9); per-request cache salting mitigates but does not eliminate.
- **Unmediated paths**: the reference returns authorized context to a trusted runtime; if the runtime discloses context without going through the release gate, AKAC controls are bypassed (operator responsibility).
- **Colluding authorized recipients**: no protection against recipients who share disclosed data with each other.
- **Model provider behavior**: AKAC cannot prevent a model provider from logging, exfiltrating, or unlearning content sent to their inference endpoint; provider approval and contract enforcement are operator responsibility.
- **Tool-use safety**: AKAC gates access to knowledge but does not prevent or audit unsafe tool invocation, code generation, or agent planning.
- **Adversarial and hallucinated content**: no automatic detection or mitigation; audit and release-gate recipient verification allow offline fact-checking.
- **Agent compromise**: if an agent's process or credentials are compromised, the attacker inherits the agent's authorization; AKAC mitigates via audit and token binding but does not prevent exploitation.

## Explicit non-guarantees

No model-weight unlearning; no recall of previously disclosed bytes; no protection against colluding authorized recipients; no constant-time query guarantee; no semantic truth guarantee; no automatic confidentiality classification; no automatic prompt-injection immunity for otherwise authorized actions; no protection of embeddings against someone who can read the vector store. Full OS compromise, external side channels and unmediated transports invalidate the boundary. No external security review or penetration test has been performed.

The reference returns raw authorized context to the trusted runtime, not directly to an arbitrary end-user browser. The release method authorizes a named recipient and returns a payload to that runtime; it does not itself transmit the message. The runtime must honor recipient binding and handle revocation races at its own transport boundary.
